# GraphDB Execution Guide

This guide explains how to inspect the generated `ontology.ttl` in Ontotext GraphDB and obtain screenshots suitable for an academic report.

## 1. Start GraphDB

Install a recent GraphDB distribution and start the local Workbench. Open:

`http://localhost:7200`

GraphDB Workbench provides Import, Explore, SPARQL, Setup, and related tools. Repository creation is available under **Setup → Repositories**.

## 2. Create a local repository

1. Open `http://localhost:7200`.
2. Select **Setup → Repositories**.
3. Choose **Create new repository**.
4. Select a GraphDB repository.
5. Use an identifier such as `urban_transport_ontology`.
6. Keep the default RDF4J/GraphDB configuration unless your installation requires otherwise.
7. Save/create the repository.
8. Select/connect to the new repository from the Workbench repository selector.

For this assignment, no special external connector is required.

## 3. Import `ontology.ttl`

1. Open **Import**.
2. Select the local/user-data RDF import workflow.
3. Choose `output/ontology.ttl`.
4. Confirm Turtle (`text/turtle`) if GraphDB does not infer the format automatically.
5. Start the import and wait for completion.
6. Optionally open the resource/class exploration views to confirm that the ontology contains classes and individuals.

The separate `output/shapes.shacl.ttl` is primarily a validation artifact. The Python pipeline already validates `ontology.ttl` with pySHACL. It does not need to be imported into the data repository for the competency queries.

## 4. Verify the ontology with SPARQL

Open **SPARQL** and run:

```sparql
PREFIX ut: <https://example.org/urban-transport#>
SELECT (COUNT(*) AS ?triples)
WHERE { ?s ?p ?o }
```

Then inspect the class inventory:

```sparql
PREFIX ut: <https://example.org/urban-transport#>
SELECT ?class (COUNT(?instance) AS ?instances)
WHERE {
  ?class a <http://www.w3.org/2002/07/owl#Class> .
  OPTIONAL { ?instance a ?class }
}
GROUP BY ?class
ORDER BY ?class
```

## 5. Run the prepared competency queries

The five queries are in `queries/`.

### Query 1 — sensors measuring speeds above threshold

Open `queries/query1.sparql`, paste it into the SPARQL editor, and run it.

Expected conceptual result: `Sensor_Shevchenka_01` is returned because its observation has an observed speed of 24.5 km/h, above the 20 km/h threshold.

### Query 2 — controllers regulating congested segments

`queries/query2.sparql` identifies controllers regulating a road segment where a peak-hour observed speed is below 60% of its allowed speed.

Expected conceptual result: `Controller_Central_01` and `RoadSegment_Shevchenka` are returned for the supplied observation.

### Query 3 — incident impact and delay

`queries/query3.sparql` connects an incident, its affected road segment, and the performance metric it causes.

Expected conceptual result: `Incident_Shevchenka_Closure`, `RoadSegment_Shevchenka`, `Metric_Shevchenka_Delay`, and delay `12.7`.

### Query 4 — transit vehicle assignments

`queries/query4.sparql` finds public-transit vehicles and their route numbers.

Expected conceptual result: `Bus_204` operates on route `8`.

### Query 5 — slow peak-hour segments and optional delay

`queries/query5.sparql` identifies road segments whose peak-hour observed speed is below 30 km/h and optionally returns a performance delay.

Expected conceptual result: `RoadSegment_Shevchenka` is returned with observed speed `24.5` and delay `12.7`.

## 6. Class hierarchy screenshot

For the report, open **Explore → Class hierarchy** after importing the ontology.

Recommended screenshot checklist:

- Browser URL visibly points to local GraphDB (`localhost:7200`).
- Repository selector shows `urban_transport_ontology`.
- The class hierarchy is visible at a readable zoom.
- Capture the hierarchy showing taxonomy groups and domain classes.
- Avoid excessive browser chrome if the report format is space-constrained.

## 7. Instance-network screenshot

Open **Explore → Visual graph**.

Use a resource such as:

`https://example.org/urban-transport#Controller_Central_01`

or search for `Controller_Central_01` using the resource/autocomplete field.

Expand neighboring nodes. A useful report screenshot should show a connected subgraph such as:

```text
TransportAuthority
       |
    manages
       |
TrafficController ---- controls ---- AdaptiveSignal
       |
    regulates
       |
  RoadSegment ---- connectsTo ---- RoadSegment
       |
    measured by
       |
TrafficSensor ---- monitors ---- TrafficObservation
```

The actual Visual Graph layout is generated by GraphDB, so node positions may differ.

## 8. Optional advanced Visual Graph configuration

GraphDB supports custom Visual Graph configurations under **Explore → Visual graph → Advanced graph configurations**. A custom configuration can use SPARQL to control starting nodes, expansion, labels, and edge labels.

For an academic screenshot, a useful starting node is `Controller_Central_01`; expand `controls`, `regulates`, and `manages` relationships. If the graph becomes too dense, collapse unrelated nodes rather than changing the ontology.

## 9. Optional SHACL validation in GraphDB

The assignment's automated validator is pySHACL, executed by `python run.py`. If the GraphDB installation provides a SHACL validation workflow, it can be used as a second/manual check, but it is not required for reproducibility of this repository.

The authoritative local validation output for the assignment is:

`reports/validation_report.txt`

## 11. Troubleshooting

### Repository is not visible

Check that GraphDB is running and that the Workbench is reachable at `http://localhost:7200`. Then use **Setup → Repositories** and connect the intended repository.

### Turtle import fails

Open `output/ontology.ttl` and verify it was generated by running:

```bash
python run.py
```

The Python generator uses RDFLib Turtle serialization, so the file should be syntactically valid.

### SPARQL returns no rows

Confirm that the correct repository is active and that `ontology.ttl` was imported. Also copy the exact `PREFIX ut:` from the prepared query files.

### Visual Graph is too dense

Start from one resource, expand only one or two relationship levels, and use the graph settings to hide predicates that are not useful for the screenshot.
