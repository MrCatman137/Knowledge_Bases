# Knowledge Extraction from Unstructured Text

Complete modular Python pipeline for an academic laboratory assignment:

**Knowledge Extraction from Unstructured Text**

Domain: **Knowledge Management & Knowledge Repositories**

The project extracts terminology and domain entities from a small technical corpus, applies rule-based relation extraction, aligns concepts to SKOS, builds RDF triples, exports Turtle, and prepares SPARQL competency queries for Ontotext GraphDB.

## 3. Requirements

- Python 3.10+
- Internet access during the first dependency/model installation
- Optional: Ontotext GraphDB for the final RDF/SPARQL stage

The preprocessing stage uses spaCy. The project automatically uses a Ukrainian model if it is installed; otherwise it falls back to `xx_ent_wiki_sm` or a lightweight built-in tokenizer/lemmatizer fallback so the complete demo remains runnable.

### Install

Windows:

```powershell
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python -m spacy download uk_core_news_sm
```

If the Ukrainian model is unavailable:

```powershell
python -m spacy download xx_ent_wiki_sm
```

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python -m spacy download uk_core_news_sm
```

## 6. Pipeline outputs

### Preprocessing

`data/preprocessed.json` contains documents, sentences, original tokens, normalized tokens, and lemmas.

### Term extraction

`data/terms.csv` contains:

- term
- weight
- accepted
- reason

The implementation uses YAKE when available. A TF-IDF fallback is included.

### NER

`data/entities.csv` contains:

- text
- normalized label
- entity_type
- source
- confidence

The domain NER is rule-based and deterministic because the corpus contains domain-specific technical concepts for which generic pretrained NER is not reliable enough.

### Relations

`data/relations.csv` contains normalized predicates:

- `uses`
- `produces`
- `defines`
- `manages`
- `part_of`
- `contains`
- `measures`
- `supports`

### SKOS alignment

`data/alignment.csv` contains:

- concept
- prefLabel
- altLabel
- broader

### Triple table

`output/triples.csv` contains:

- subject
- predicate
- object
- source
- confidence

The builder intentionally combines relation triples, entity typing, SKOS labels, and hierarchy information to produce a graph suitable for GraphDB.

## 7. RDF model

The Turtle exporter uses:

```text
@prefix :     <http://example.org/kmkg/> .
@prefix skos: <http://www.w3.org/2004/02/skos/core#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@prefix rdf:  <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
```

The default namespace is therefore `:` as required by the assignment.

## 8. GraphDB manual

### 8.1 Launch GraphDB

Install GraphDB Desktop or the local GraphDB distribution from Ontotext.

Start GraphDB and open:

```text
http://localhost:7200
```

If the service is running, the GraphDB Workbench interface is displayed.

### 8.2 Create a repository

1. Open GraphDB Workbench.
2. Select **Setup** / **Repositories**.
3. Click **Create new repository**.
4. Choose the RDF4J repository configuration.
5. Give it a name such as:

```text
knowledge-extraction
```

6. Keep the default RDF configuration unless your instructor requires another setup.
7. Save/create the repository.
8. Select the new repository.

### 8.3 Import Turtle

After running:

```bash
python main.py
```

open:

```text
output/knowledge_graph.ttl
```

In GraphDB:

1. Select **Import**.
2. Choose **Upload RDF files** / local file import.
3. Select `knowledge_graph.ttl`.
4. Confirm the import.
5. Wait for the import to finish.

The repository should now contain the generated RDF graph.

### 8.4 Execute SPARQL

Open **SPARQL** in GraphDB.

Copy one query from:

```text
queries/query1.sparql
```

and execute it.

Repeat for:

```text
query2.sparql
query3.sparql
query4.sparql
```

### 8.5 Suggested report screenshots

Take screenshots of:

## 9. Competency questions

The supplied queries answer questions such as:

1. Which processes use a selected artifact?
2. Which roles define a selected metric?
3. Which concepts are broader/narrower than a selected concept?
4. Which artifacts are produced or managed by processes?

## 10. Evaluation

See `evaluation.md`.

It contains a manual review of 30 generated triples, precision calculation, and common extraction error cases with root-cause explanations.

## 11. Reproducibility

The corpus is fixed and the extraction rules are deterministic. Therefore, the generated graph is reproducible on another machine with the same source corpus and compatible dependencies.

The exact confidence values are heuristic extraction confidence values, not statistical probabilities.

## 12. Academic note

The NER and relation extraction components deliberately use transparent domain rules rather than claiming that a general-purpose language model has performed perfect semantic extraction. This makes the result easier to inspect, explain, and defend during a laboratory demonstration.
